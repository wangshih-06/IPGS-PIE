## 2. 数据结构关系

```text
PlantModel
├── PlantNode rootNode
│   └── children: vector<unique_ptr<PlantNode>>
├── Branch[]  // 对应每一条父节点 -> 子节点骨架边
├── Leaf[]    // 通过 parentNodeId 挂接到骨架节点
└── Root[]    // 通过 parentNodeId 挂接到骨架节点
```

`PlantNode` 同时保存：

- `id`：稳定节点 ID；
- `parentId`：用于 JSON、网络传输和数据库存储；
- `parent`：运行时向上遍历指针，不参与序列化；
- `children`：使用 `std::unique_ptr` 明确节点所有权；
- `position`、`direction`、`radius`、`length`：骨架几何信息；
- `age`、`depth`、`active`：年龄、拓扑深度与生长活跃状态；
- `type`：主干、分枝、芽点或根节点类型；
- `generation`：L-System 分枝层级，与逐段递增的 `depth` 分开保存。

植物整体保存 `age`、`lifeStage` 和 `growthState`。其中生命周期包括种子、幼苗、营养生长、成熟、开花、休眠和衰老；生长状态包括活跃、暂停、休眠、胁迫和完成。

## 3. JSON 格式

JSON 根对象采用带版本的格式：

```json
{
  "schema": "plantsim.skeleton",
  "version": 1,
  "plant": {
    "id": 1001,
    "name": "Week 4 Demo Tree",
    "species": "Prunus serrulata",
    "age": 2.5,
    "lifeStage": "vegetative",
    "growthState": "active"
  },
  "skeleton": {
    "rootNodeId": 0,
    "nodes": [],
    "branches": [],
    "leaves": [],
    "roots": []
  }
}
```

节点使用扁平数组保存，父子关系由 `parentId` 重建。加载器会检查：

1. schema 与版本；
2. 节点 ID 唯一性；
3. 根节点及父节点引用；
4. 循环、断开的节点和错误的 `depth`；
5. 每条 `Branch` 是否与真实父子边一致；
6. 叶片和根系的挂接节点是否合法；
7. 半径、长度、年龄、健康度等数值是否合法。

`PlantModel::saveJson()` 和 `PlantModel::loadJson()` 分别实现序列化与反序列化。示例文件位于 `examples/plant_skeleton.json`。

## 5. 与现有生长系统的集成

`SimulationEngine` 现在持有完整 `PlantModel`。原有 `TurtleInterpreter` 仍生成 `unique_ptr<PlantNode>` 树，随后由 `PlantModel::setRootNode()`：

- 分配或修正稳定节点 ID；
- 建立 `parent`、`parentId` 和 `depth`；
- 从骨架父子边自动生成 `Branch` 列表。

因此现有 L-System 功能保持兼容，后续生长、物理、隐式曲面和交互编辑模块都可以直接使用统一植物模型。
